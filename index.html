Does it matter where your images live?

This page loads the same image file from two or more hosts, one request at a time, and times each one in your browser. Nothing is simulated and nothing is sent anywhere — the measurements are the browser's own Resource Timing numbers, taken on your connection, from wherever you happen to be sitting.

How to read these numbers

A single run tells you very little. Networks are noisy, and the first request to a host pays for a DNS lookup, a TCP handshake and a TLS negotiation that later requests reuse. That is why this page runs several times, alternates between hosts, and reports the median rather than the average — one unlucky run cannot drag the median around the way it drags a mean.

The two modes measure genuinely different things

Repeat visitor is the default, and the one that answers "where should my images live". Each request goes to a stable URL with only the browser cache bypassed, so a host with a CDN in front of it answers from its edge — which is what almost every real visitor gets, because someone near them has usually fetched the file already. This is the mode in which a CDN is allowed to show what it is for.

First visitor adds a unique ?cb= token to every URL. That misses the browser cache and the CDN edge alike, so each request travels all the way to the origin. It is the honest worst case, and it is the right mode for asking how quickly a host can produce a file it is not already holding near you — but reading it as the everyday number understates any host with a cache in front of it.

Repeat-visitor mode needs every host to permit a cross-origin read, because it is the only way to bypass the browser cache without changing the URL. If any one host refuses, the page says so and drops all hosts back to first-visitor mode — measuring two hosts by different methods would be worse than measuring them both pessimistically.

Whether the difference is real

A ratio on its own is not a result. If the run-to-run spread is wider than the gap being claimed, the ranking is noise dressed up as a finding. The page runs a Mann–Whitney U test on the two fastest hosts' samples — a rank test, because latencies are skewed and the samples are small — and says plainly whether the ordering survives. When it does not, the headline reads Too close to call rather than inventing a winner.

It also proves the hosts served the same file. Where a cross-origin read is permitted, the byte count is taken from the response body itself rather than from a header, so a host quietly serving a smaller or re-encoded image is caught and the comparison is flagged as not like-for-like.

Why the two hosts are not really the same kind of thing

  • raw.githubusercontent.com is a convenience endpoint for reading files out of a repository. It is rate limited, it is not a CDN contract, and GitHub's terms do not cover using it as a production asset host. It is a great "does this work" URL and a poor place to point a live site.
  • GitHub Pages (username.github.io) is a real static host with a CDN in front of it. If you want the GitHub side of this comparison to be a fair fight, this is the URL to use, not the raw one.
  • Backblaze B2 is object storage. Hitting the bucket endpoint directly (f00x.backblazeb2.com) means going to one region every time, from anywhere in the world. Putting Cloudflare in front of it — the img.yourdomain.com arrangement — adds a cache at the edge and, through the Bandwidth Alliance, makes egress free. That is where B2 starts to look good on both speed and the bill.

So the interesting comparison is usually not "GitHub or Backblaze" but "is there a CDN in front of it, and how far is the origin from the visitor". All three are filled in above — raw GitHub, direct B2, and the same B2 bucket behind Cloudflare — and the shape of the answer usually appears in the first eight runs. The third one is the arrangement worth copying; the gap between it and the second is what the CDN is buying you.

Things this page cannot see

  • Cross-origin hosts only expose a phase-by-phase breakdown (DNS, connect, TLS, waiting, downloading) if they send a Timing-Allow-Origin header. Where a host does not, the table falls back to the total, and says so.
  • Transferred byte counts have the same restriction. If a size reads as unknown, check that the two hosts really are serving the same file before trusting the comparison — one of them may be re-encoding or resizing it.
  • Your result is your result: your city, your ISP, your Wi-Fi, this minute. It is evidence about your visitors only to the extent that they sit where you sit.
